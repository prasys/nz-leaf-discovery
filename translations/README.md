# translations/

The English voice tables. Tools read these files; nothing here is read from a
card at runtime. Audio and GIDs live under `$NISSAN_ROOT/work/` and only their
SHA256 values are pinned in the repo.

| File | What | Read by |
|---|---|---|
| `voice-prompts.tsv` | Every recorded GID clip (2,071) and playlist, with a Japanese ASR draft and NZ English | People; regenerated by `tools/language-speech/build_voice_table.py` |
| `voice-prompt-overrides.tsv` | The reviewed subset: locked greeting/EV wording and corrected rows | `build_voice_table.py`, `greeting.py` |
| `greeting-slot-fits.tsv`, `ev-slot-fits.tsv` | Per-clip slot sizes and fit results for the Penny builds | `clip_pack.py list`; reference for `prepare_greeting.py` |

## Columns

`voice-prompts.tsv`: `id/offset`, `category`, `jp_text`, `en_nz`, `status`,
`used_by`, `nz_relevance`, `notes`. `voice-prompt-overrides.tsv` has `clip`
instead of `id/offset`.

- `status`: `draft` (machine ASR and translation), `reviewed` (wording checked
  for language), `locked` (exact wording approved by the owner; greeting/EV rows
  also need `wording locked` and a confidence tag in `notes`, or `greeting.py`
  refuses to render), `in-car` (in a pinned build written to a card; build hash
  in `notes`).
- `used_by`: the firmware module or phrase ID that plays the clip, where traced.
- `nz_relevance`: blank, or `no` for Japan-only material (ETC tolls, JMA weather,
  Japanese place names). Rows are flagged, never deleted.
- `notes`: evidence and confidence. Every ASR correction is tagged
  `[likely]` or `[guess]`.

A row moves `draft` → `reviewed` → `locked` → `in-car`. A wording change after
`locked` goes back to `reviewed` and through a new build.

`build_voice_table.py` still writes only the five base columns; regenerate into
a temporary file and keep the lifecycle columns.

Your own wording for a build doesn't go here: put it in a `VOICE_WORDING` file
outside the repo (`docs/guides/english-voice.md`).
